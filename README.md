# STOREX — статический сайт

Готовый многостраничный сайт на русском, казахском и английском языках: **HTML, CSS, JavaScript, локальные шрифты и изображения**. На хостинге не требуются Node.js, Next.js, база данных или Sites. Анимации, переключение языка, фильтры проектов и форма работают в браузере.

Next.js App Router, React, TypeScript и Tailwind CSS используются для разработки и генерации файлов. Итоговый сайт находится в **`out/`**. Передаваемый отдельно `storex-static.zip` содержит готовую папку для загрузки на хостинг; `storex-source.zip` — исходники для редактирования и пересборки.

## Размещение готовой версии

1. Распакуйте `storex-static.zip`.
2. Загрузите всё содержимое, включая `_next`, `images`, `.htaccess` и языковые папки, в корневую папку сайта (`public_html`, `www` или аналогичную).
3. Откройте домен. `index.html` перенаправляет на `/ru/`; переключатель RU / ҚАЗ / EN сохраняет текущую страницу.
4. Для формы укажите URL внешнего обработчика в `contact-config.json` — инструкция ниже.

Сборка рассчитана на корень домена. Для публикации в подпапке потребуется настройка `basePath` и путей к ресурсам с пересборкой. Не открывайте сайт двойным кликом через `file://`: используйте локальный HTTP-сервер или хостинг.

В статическом архиве уже находятся `ru/index.html`, `kk/index.html`, `en/index.html`, страницы услуг и проектов, `sitemap.xml`, `robots.txt`, `404.html`. Всего 48 содержательных страниц. SEO-ссылки собраны для **https://storex.kz** из материалов компании; при другом домене измените `SITE_URL` перед сборкой.

Apache: вложенный `.htaccess` задаёт индекс и страницу 404. Для Nginx достаточно:

```nginx
root /var/www/storex;
index index.html;
location / { try_files $uri $uri/ =404; }
error_page 404 /404.html;
```

На другом статическом хостинге настройте `404.html` как страницу ошибки. Её текст автоматически выбирается по префиксу `/ru/`, `/kk/` или `/en/`.

## Локальный просмотр готовой сборки

Из папки исходников, при установленном Node.js:

```powershell
node scripts/serve-static.mjs
```

Открыть **http://127.0.0.1:3001/ru/**. Это обычный локальный файловый сервер, а не сервер Next.js. Другой порт: `node scripts/serve-static.mjs --port 8080`.

Если Node.js не установлен, можно просмотреть содержимое `out/` любым HTTP-сервером, например `python -m http.server 8080 --directory out`. Python-сервер подходит для просмотра страниц; пользовательскую страницу 404 нужно проверять на сервере с соответствующей настройкой.

## Внешний обработчик формы

В готовой сборке откройте `contact-config.json` и укажите публичный HTTPS-адрес:

```json
{
  "endpoint": "https://ваш-обработчик.example/"
}
```

Пересборка не нужна. Пока адрес пуст, форма сообщает о недоступности отправки, предлагает email/телефон и сохраняет введённые данные. Секретных ключей в статическом сайте нет. Реальный обработчик не опубликован, почтовый аккаунт не подключён, проверочные письма не отправлялись.

В `integrations/contact-worker.ts` подготовлен отдельный обработчик с CORS, ограничением размера запроса, проверкой полей, honeypot и отправкой на **info@storex.kz** через Resend. Его можно разместить отдельно как Cloudflare Worker. Настройки приведены в `integrations/wrangler.jsonc`.

Для подключения через Cloudflare Workers:

1. Создайте аккаунт Resend, подтвердите домен отправителя и получите API-ключ.
2. В `integrations/wrangler.jsonc` задайте `ALLOWED_ORIGIN` равным точному адресу сайта, например `https://storex.kz` (схема и поддомен должны совпадать).
3. В своём аккаунте Cloudflare задайте секреты `RESEND_API_KEY` и `CONTACT_FROM` для обработчика; `CONTACT_FROM` должен содержать адрес подтверждённого домена.
4. Опубликуйте обработчик отдельно и скопируйте его HTTPS-адрес в `contact-config.json`.
5. Отправьте контрольное обращение и проверьте получение письма в Storex.

При использовании Wrangler из каталога проекта:

```powershell
pnpm dlx wrangler deploy --config integrations/wrangler.jsonc
pnpm dlx wrangler secret put RESEND_API_KEY --config integrations/wrangler.jsonc
pnpm dlx wrangler secret put CONTACT_FROM --config integrations/wrangler.jsonc
```

Эти команды публикуют только внешний обработчик и выполняются пользователем после настройки аккаунта. До появления почтовых секретов обработчик возвращает `UNAVAILABLE`. Секреты хранятся в окружении обработчика, не в `contact-config.json`. Подробнее: [секреты Cloudflare Workers](https://developers.cloudflare.com/workers/configuration/secrets/) и [настройка Wrangler](https://developers.cloudflare.com/workers/wrangler/configuration/).

Можно использовать свой обработчик вместо Workers. Контракт:

```json
{
  "name": "Имя",
  "company": "Компания",
  "email": "person@example.com",
  "phone": "",
  "message": "Описание задачи длиной не менее 10 символов",
  "consent": true,
  "locale": "ru",
  "website": ""
}
```

Метод POST, Content-Type `application/json`. Обработчик должен разрешать CORS для домена сайта и запрос OPTIONS. Успех: `200 {"ok":true}` только после принятия письма сервисом. Ошибки: `INVALID` (400), `UNAVAILABLE` (503), `DELIVERY_FAILED` (502). Интерфейс блокирует повторное нажатие и не показывает успех при сетевой ошибке. В подготовленном обработчике отправка выполняется простым текстом; email посетителя используется как Reply-To.

## Изменения и пересборка

Требуется Node.js 20.9+ и pnpm:

```powershell
pnpm install
pnpm dev
```

Для разработки открывайте http://127.0.0.1:3000/ru/. Корневой HTML-переход и статическая 404 добавляются при финальной сборке.

```powershell
pnpm test
pnpm build
pnpm typecheck
pnpm preview
```

`pnpm build` генерирует `out/`, затем добавляет корневую страницу, локализованную 404 и настройки статического размещения. Если меняли `contact-config.json` непосредственно на хостинге, перенесите его адрес в `public/contact-config.json` перед следующей сборкой.

## Где редактировать

- `src/lib/content.ts` — все тексты, переводы, направления и проекты.
- `src/app/[locale]/[[...path]]/page.tsx` — структура страниц и SEO.
- `src/components/` — навигация, схема, секции, фильтры и форма.
- `src/app/globals.css` — визуальная система и адаптивная вёрстка.
- `public/images/` — оригинальный логотип и фотографии из PDF в WebP.
- `public/contact-config.json` — только публичный URL внешнего обработчика.
- `src/lib/contact.ts` и `integrations/` — отдельно размещаемая почтовая интеграция; в `out/` эти серверные модули не включаются.
- `CONTENT_SOURCES.md` — происхождение фактов и изображений.
- `VERIFICATION.md` — результаты проверки.

Новый проект добавляется в массив `projects` со стабильным slug, тремя переводами и фотографиями. Страница и sitemap создаются при сборке. Аналогично добавляются направления в `services`.

Публичная публикация сайта и обработчика, подключение реального почтового аккаунта и изменение существующего домена не выполнялись.
